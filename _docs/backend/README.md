## Overview

The backend directory contains the FastAPI application entry (main.py) which exposes HTTP endpoints for generation, release management, file access, and an optional background bot queue. At the root there are several support modules (listed in the repository but not fully documented here) such as bot.py, media.py, pipeline.py, storage.py, and environment and containerization files (.env.example, Dockerfile, .dockerignore, entrypoint.sh, requirements.txt). The main.py module is the primary application module and is the runtime entry point that wires endpoints and optional background processing together.

A dedicated connectors/ subdirectory contains concrete connector implementations and minimal glue code to integrate external distribution providers. The connectors directory specifically includes a RouteNote connector implementation (routenote.py) and supporting Distributor subclasses and helper modules. Together, root-level modules (request handling, media and storage helpers, bot queue, and pipeline) and the connectors integrations enable the backend to receive requests, manage release and file operations, dispatch distribution actions to external providers, and optionally run background tasks for queued work. This structure positions the backend as the core HTTP API and integration layer for the overall system.


### File Organization

Root contains the FastAPI app entry and supporting modules for media, storage, pipeline, bot, and container/environment files. Integration-specific code is isolated in the connectors/ subdirectory to keep external provider implementations separate from core request handling and business logic.

## Architecture Notes

- The FastAPI application (main.py) is the central entry point; connectors are isolated in a dedicated subdirectory to separate provider-specific code from core API logic.
- Background bot queue is optional and integrated so long-running or asynchronous distribution tasks can be processed separately from HTTP request handling.
