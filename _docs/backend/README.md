## Overview

The backend directory contains the primary web application entry point and the supporting components required to handle HTTP requests related to generation, release management, file access, and an optional background bot queue. At the root level the documented main.py defines a FastAPI application object (app) that exposes these HTTP endpoints; other root-level modules (listed but not documented here) provide additional runtime helpers, CI/smoke tests, storage, media and pipeline utilities, a bot, and container configuration. Together, the root modules implement the runtime surface and operational scripts for starting and running the backend service.

A dedicated connectors subdirectory holds adapter implementations that integrate external distributor services into the system via a Distributor abstraction. The connectors directory provides concrete integration points for downstream delivery; for example, a RouteNote connector implementation is present to adapt that specific distributor into the system's Distributor interface. These connectors are used by the FastAPI application and related modules to deliver generated artifacts to external distributors. Overall, this directory's components work together to accept API requests (main.py), manage file/media/pipeline operations (other root modules), and hand off distribution tasks through connector implementations in connectors/ to external services, forming the backend surface of the larger system.


### File Organization

Top-level entry points and runtime scripts live at the root (including the FastAPI app in main.py). Integration points that adapt external services are grouped under connectors/. Other helper modules and operational scripts are kept at the root to separate application entry logic from connector implementations.

## Architecture Notes

- The application separates the HTTP surface (main.py) from external service adapters (connectors/) via a Distributor abstraction, allowing connectors to be implemented or swapped independently of endpoint logic.
- Root-level modules provide operational scripts and helpers while connectors encapsulate third-party integration code, promoting separation of concerns between application flow and external delivery mechanisms.
