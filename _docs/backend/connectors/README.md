## Overview

This directory contains connector implementations that implement the Distributor abstraction used by the system. At the root level there is a concrete connector implementation routenote.py which implements a RouteNote connector as a Distributor subclass. The routenote.py module provides the code that maps the application's Distributor interface to RouteNote-specific behaviors and is the primary entry point for RouteNote integration.

In addition to the concrete connector modules at the root, the directory includes supporting package files such as __init__.py and base.py (listed but not documented here). base.py is present in the directory (not described in detail above) and, given routenote.py's purpose as a Distributor subclass, serves as the shared base or abstraction that connector modules extend. Together, the root-level connector implementations and the base abstraction provide a clear separation between framework-level Distributor definitions and service-specific integration logic, enabling easy addition or modification of connectors without changing core application code.


### File Organization

Connector implementations (service-specific adapters) live at the directory root alongside package bootstrap and base abstraction files. Each connector (for example routenote.py) extends the shared base defined in base.py, allowing consistent usage across the application. This groups related adapter logic together and isolates third-party integration code from higher-level business logic.

## Architecture Notes

- Connectors are implemented as subclasses of a shared Distributor abstraction (located in base.py) to separate service-specific integration from the rest of the application.
- Each connector module contains the adapter logic for a single external distributor service, promoting single-responsibility and easier testing.
